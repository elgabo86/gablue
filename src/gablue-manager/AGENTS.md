# Gablue Manager — paquet `gablue_manager` (src/gablue-manager)

GUI PySide6 (Wayland natif) : liste des postes SSH avec état et latence, bureau distant (`gremote`), fichiers (`dolphin sftp://`), terminal SSH, réveil Wake-on-LAN, arrêt / redémarrage / mise à jour des postes, découverte mDNS, import de `~/.ssh/config`, ajout + copie de clé — **et la machine courante** : serveur SSH, annonce mDNS, mises à jour (image Gablue, Flatpaks, gwine) et options avancées (ex-`gablue-config`), services et variante de l'image (ex-recettes ujust). Nom affiché « Gablue Manager » ; binaire et `.desktop` = `gablue-manager` / `gablue-manager.desktop` (convention `gablue-*`), **catégorie Système** (`Categories=System;`) et icône maison `gablue-manager` (`/usr/share/icons/hicolor/scalable/apps/gablue-manager.svg` : carré bleu Gablue, anneau en **engrenage à 8 dents** formant un G — ouverture en haut à droite et barre horizontale, le tout en une seule silhouette), avec repli `network-server` hors image via `uiutil.app_icon()`. Remplace l'ancien `gablue-ssh`, `/usr/libexec/gablue-config` (script kdialog supprimé, ainsi que `gablueconfig.desktop` et son entrée de blacklist) et `gablue-update` (script Python et `gablueupdate.desktop` supprimés, ainsi que son entrée de blacklist, la recette `ujust gablue-update`, l'alias `gablue-update` et la ligne d'aide correspondante) : les mises à jour se lancent depuis la carte « Ce poste ».

## Paquet

Sources = ce dossier (`src/gablue-manager/`), installées par
`files/scripts/build-manager` :

| Fichier | Rôle |
|---|---|
| `gablue-manager` | lanceur `/usr/bin/gablue-manager` : ajoute `/usr/lib/gablue-manager` (ou le dossier courant en développement) au `sys.path` puis `gablue_manager.app.main()` |
| `gablue_manager/app.py` | `HELP` et `main()` (QApplication, QSS, fenêtre) |
| `gablue_manager/constants.py` | chemins, binaires (`_which`), couleurs et textes d'état, constantes kargs/helpers |
| `gablue_manager/util.py` | cible ssh, nom affiché, URL KIO, normalisation MAC, options ssh communes |
| `gablue_manager/hosts.py` | registre `ssh-hosts.json`, découverte mDNS, import `~/.ssh/config`, Wake-on-LAN |
| `gablue_manager/ssh.py` | empreintes d'hôte, copie de clé, exécution distante, sudo distant |
| `gablue_manager/local.py` | état/commandes de la machine (sshd, avahi, kargs, CPUID, services, variante, atuin, gwine, booster, Tailscale) |
| `gablue_manager/apps.py` | applications AppImage (émulateurs + OpenCode 2) : état, GearLever, install/config/suppression |
| `gablue_manager/workers.py` | threads : vérification des postes, clé, commande ssh, découverte |
| `gablue_manager/style.py` | QSS adapté au thème Plasma |
| `gablue_manager/uiutil.py` | `restyle_label`, `fit_dialog_height`, `recommendation_badge` |
| `gablue_manager/tasks.py` | `start_task`, dialogues de tâche locale/distante (non modaux) |
| `gablue_manager/widgets.py` | `StatusDot`, `HostCard`, `LocalCard` |
| `gablue_manager/dialogs/` | un fichier par dialogue (`host`, `key`, `kernel`, `gwine`, `booster`, `tailscale`, `apps`) |
| `gablue_manager/window.py` | `MainWindow` |
| `tests/` | tests unitaires stdlib des fonctions pures |

**Règle** : le paquet est la source de vérité ; ne pas réintroduire de fichier
unique assemblé. Un nouveau dialogue → un fichier dans `dialogs/` + une entrée
de menu dans `window.py`. Les imports relatifs vont dans un seul sens
(`constants ← util ← hosts/ssh/local ← workers/tasks ← dialogs ← window ← app`) :
un cycle (ex. `_ssh_opts` entre `hosts` et `ssh`) se règle en descendant la
fonction dans le module le plus bas, pas par un import tardif.

## Build

- `Containerfile-gablue` : `COPY src/gablue-manager /src/gablue-manager`, puis
  `RUN /ctx/build-manager` juste après `build-gwine`.
- `files/scripts/build-manager` : copie `gablue_manager/` dans
  `/usr/lib/gablue-manager/`, installe le lanceur en `/usr/bin/gablue-manager`
  (755) et retire les `__pycache__` (le Python du build n'est pas celui du
  poste, `/usr` est en lecture seule sur composefs).
- Développement : `src/gablue-manager/gablue-manager --help` marche depuis le
  dépôt ; `PYTHONPATH=src/gablue-manager python3 -c "import gablue_manager.app"`.
- L'image doit être reconstruite pour valider l'installation (pas l'ISO).

## Comportement

- **Registre** `~/.config/gablue/ssh-hosts.json` (dossier 0700, fichier 0600, écriture atomique `mkstemp` + `os.replace`) : source de vérité de l'app. Un poste ajouté uniquement par `ssh-key-add` en CLI n'y figure pas (le script ne consigne rien) — d'où l'import `~/.ssh/config`. Registre illisible → renommé `ssh-hosts.corrupt-<horodatage>.json`, jamais écrasé. Champ `mac` (WoL) capturé au premier check réussi : table ARP, sinon `/sys/class/net/<iface>/address` par SSH.
- **État** : `ssh -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes -o BatchMode=yes -o StrictHostKeyChecking=yes -p N … true`, 6 postes en parallèle, relance toutes les 30 s, test annulable à la fermeture. `BatchMode` + `IdentitiesOnly` = c'est bien NOTRE clé qui est testée ; pas d'`accept-new` ici, un simple ping ne doit pas écrire dans `known_hosts`. Vert = clé acceptée, orange = joignable mais clé refusée, violet = empreinte d'hôte inconnue, gris = hors ligne / DNS. **Latence** = durée du handshake SSH complet : pas de connexion TCP nue en plus, sinon sshd verrait une sonde vide toutes les 30 s (et la compte dans ses pénalités). Tri en ligne d'abord, réordonné seulement en fin de passe ; rafraîchissement au retour de focus si le dernier date de > 8 s.
- **Copie de clé** : `ssh-copy-id` dans un vrai pty (session + `TIOCSCTTY`) pour que l'invite « password: » soit alimentée ; mot de passe jamais en argv ni enregistré, champ vidé après usage. Le probe `BatchMode` final fait foi, pas le code retour de ssh-copy-id. **Vérification préalable** (`KeyProbeWorker`) : le dialogue sonde d'abord si la clé est déjà acceptée et n'affiche le champ mot de passe qu'ensuite — un poste qui répond à la clé n'en demande aucun (titre « Clé déjà installée sur … », simple bouton Fermer) ; la sonde est bornée par les délais ssh (4 s) et Fermer reste désactivé pendant ce temps pour ne pas détruire le thread en vol. **L'ajout d'un poste inclut la copie** : `HostDialog` n'a plus qu'un bouton « Ajouter » (le mot de passe, facultatif, y est saisi une fois) et la fenêtre de clé démarre la copie **d'elle-même** quand ce mot de passe est fourni (`_initial_password` → `_start`, une seule fois) ; un import de plusieurs postes (mDNS, `~/.ssh/config`) passe par `_install_keys` : une sonde muette par poste (thread), clé marquée installée quand elle passe, et le dialogue ne s'ouvre que pour ceux qui la refusent encore, **un à la fois** (le suivant attend la fermeture du précédent). Rien n'est demandé sur un poste qui accepte déjà la clé.
- **Empreinte d'hôte** : `ssh-keyscan` → empreintes SHA256 affichées, accord explicite, puis **épinglage des clés exactes** dans `known_hosts` (jamais `accept-new`) ; empreinte différente = refus (MITM), scan muet = refus (pas de trust à l'aveugle).
- **Actions distantes** : terminal (`konsole -e ssh`), arrêt / redémarrage (`systemctl poweroff|reboot`, code 255 « connection closed » = succès normal), et **les mêmes mises à jour que la machine courante** via le menu « Mettre à jour » de la carte : image Gablue (`sudo -n bootc upgrade` puis `bootc status`, `staged` → redémarrage requis), Flatpaks (même script qu'en local : `flatpak update --user -y` puis `sudo -n flatpak update --system -y`, donc sans mot de passe sur un poste Gablue, repli direct sinon), gwine (`gwine --init`). Journal en direct, annulable.
- **Options avancées à distance** : `RemoteSettingsDialog` lit l'état en **une seule connexion SSH** (`rpm-ostree kargs`, repli `cat /proc/cmdline`, plus la présence de `/etc/modules-load.d/gablue-cpuid-emu.conf`) et propose les mêmes quatre cases qu'en local, appliquées par les mêmes helpers (`sudo -n gablue-kargs`, `gablue-cpuid-emu`). **sudo à distance** : `remote_helpers_nopasswd()` sonde `sudo -n gablue-cpuid-emu status` (0 = règle NOPASSWD présente) ; sinon `QInputDialog` (écho masqué, jamais enregistré) puis `sudo -S -p '' -v` valide le cache une fois — le mot de passe part sur **stdin du ssh**, jamais dans argv — et le reste du script utilise `sudo -n`. Le chemin sert aussi au redémarrage et à l'extinction. `sudo -n true` ne sert PAS de sonde : aucune règle pour `true`, même sur Gablue ; `sudo -l` rend 0 dans tous les cas.
- **Découverte / import** : `avahi-browse -rtp _ssh._tcp` et parsing de `~/.ssh/config` `Include` compris (motifs `* ? !` ignorés), dans une liste à cocher **vide au départ** — rien n'entre dans le registre sans validation explicite (bouton « Ajouter (N) » désactivé tant que rien n'est coché, « Tout cocher » pour l'inverse) ; la découverte propose, elle n'ajoute pas. Les deux sont des entrées du menu du bouton **« Ajouter un poste »** (avec la saisie manuelle), pas des commandes séparées. **Une ligne par machine, pas par adresse** : Avahi annonce une adresse par interface du poste (boucle locale, `docker0`, `tailscale0`, LAN…), d'où quatre lignes pour un seul poste constaté le 05/11/2026. `hosts.group_candidates` écarte ce qui n'est pas joignable d'ici — boucle locale, `169.254/16`, **nos propres adresses** (une adresse identique à la nôtre est forcément l'interface du poste, pas la sienne), et toute adresse hors de nos sous-réseaux directs **sauf Tailscale** (`100.64.0.0/10`) — puis regroupe par nom mDNS + utilisateur + port et trie LAN avant Tailscale (l'adresse LAN est le défaut). L'interface locale est lue par `ip -o -4 addr show` (`hosts.parse_local_ipv4`, table vide = filtre permissif). Dans le dialogue, un poste à plusieurs adresses affiche une liste déroulante (« 192.168.1.109 (LAN) », « 100.64.0.45 (Tailscale) ») : c'est l'adresse choisie qui est enregistrée. Un poste déjà connu par **n'importe laquelle** de ses adresses n'est pas reproposé.
- **Serveur SSH local** : pastille au pied de page, `systemctl is-active`/`is-enabled`, bascule `sudo -n systemctl enable|disable sshd.service --now` (même effet que `ujust ssh-on/off`) ; si sudo réclame un mot de passe (hors image Gablue), repli `pkexec` via `QProcess` (dialogue PolicyKit, bouton désactivé pendant l'attente) — jamais de `sudo` bloquant sur le thread GUI.
- **Annonce mDNS de ce poste** : seconde pastille du pied de page, lit la présence de `/etc/avahi/services/ssh.service` et l'état d'`avahi-daemon`. Activation = fichier XML `_ssh._tcp` port 22 (`<name replace-wildcards="yes">%h</name>`) écrit en temporaire 0644 puis `install -m 644` ; désactivation = `rm -f`. Avahi surveille le dossier et recharge seul (~1 s), aucun `systemctl restart`. Même schéma `sudo -n` → `pkexec`. **Pourquoi ce bouton** : le preset Fedora active bien `avahi-daemon`, mais `/usr/share/avahi/services/` est vide — sshd n'est donc jamais annoncé et la découverte de `gablue-manager` ne trouve rien sur un poste stock. L'annonce est **lien-local** (multicast `224.0.0.251:5353`, non routé) et ne publie que nom d'hôte, IP et port — aucun compte, aucune clé ; un poste qui s'y ferait passer pour un autre est bloqué par l'épinglage d'empreinte. Daemon arrêté → la pastille le dit et refuse la bascule (`sudo systemctl enable --now avahi-daemon`).
- **Bureau distant — relance sans erreur** : chaque clic ouvre une **nouvelle fenêtre**, même si une session tourne déjà (une seule session KRdp par utilisateur : le nouveau client coupe le précédent et sort en **2**, `STATE_RUN_QUIT`). Le code 2 est ignoré, comme le 131 de fermeture normale de `sdl-freerdp`, sinon un faux dialogue « La commande a échoué (code 2) » apparaissait à chaque reconnexion. Les sessions lancées par l'app restent suivies par poste (`host_id`, `kind="remote"`) : l'entrée **« Fermer la session de bureau distant »** du menu ⋯ n'est active que s'il y en a une, demande confirmation (défaut : non), puis envoie SIGTERM au groupe (SIGKILL après 3 s) pour que `gremote` nettoie tunnel SSH, serveur RDP et puits audio ; fermer la fenêtre à la main la désactive au poll suivant. Supprimer un poste ferme ses sessions.
- **Carte « Ce poste »** : fixe au-dessus de la liste (indépendante des postes enregistrés), nom d'hôte + utilisateur + `PRETTY_NAME` de `/etc/os-release`. Reprend les métriques des cartes de postes — hauteur 92, icône dans un emplacement de 26 px comme la pastille d'état, mêmes marges — sinon texte et boutons se décalent de 2 px d'une carte à l'autre ; tous les boutons ont la même hauteur (le style `accent` a le même rembourrage vertical que le style par défaut). Le bouton **« Configuration »** est un menu à quatre entrées : réglages du noyau, options de gwine, priorité au premier plan, Tailscale (chaque dialogue applique ses changements d'un coup). Menu **« Mettre à jour »** : image Gablue (`bootc upgrade`, appliquée au prochain démarrage), Flatpaks (`flatpak update --user -y` puis `sudo -n flatpak update --system -y` — la règle sudoers de l'image évite tout mot de passe ; hors image Gablue, repli sur l'appel direct et son dialogue PolicyKit), gwine (`gwine --init`, runner et composants DXVK/VKD3D). Chaque action est confirmée puis suivie dans `LocalTaskDialog` (QProcess, canaux fusionnés, annulation par `setsid`, codes 125/126/127 traduits).
- **Applications** (bouton « Applications » de la carte « Ce poste » et entrée « Applications… » du menu ⋯ d'un poste) : dialogue **non modal** en deux sections, « Émulateurs » (ES-DE, Azahar, Eden, Xenia, ShadPS4) et « Outils » (OpenCode 2), avec pour chaque ligne l'état (AppImage `~/AppImages`, version GearLever, version CLI quand il y en a une), un bouton **Installer/Mettre à jour** et **Supprimer**. **Local et distant** partagent le même dialogue (`host=None` ou un poste) : à distance l'état est lu en **une seule connexion SSH** (`REMOTE_STATE_SCRIPT` : GearLever, `ls ~/AppImages`, `opencode --version`, chemins des scripts + options qu'ils connaissent, découpé par `parse_remote_state`/`remote_states`) et les actions passent par `RemoteTaskDialog`, jamais par un `exec()` ; poste injoignable → lignes « État indisponible » et boutons désactivés. Aucune logique de téléchargement n'est réimplémentée : le manager lance le script existant de l'image (`esde-install`, `azahar-install`, `eden-install`, `xenia-install`, `shadps4-install`, `opencode2-install`) et affiche son journal ; ES-DE reçoit `--yes` (le journal remplace ses boîtes kdialog) et expose en plus **« Mettre à jour la config »** (`--config-only` : `custom_systems` + lanceurs Tools, sans toucher à l'AppImage). **Le manager lit le script pour savoir ce qu'il accepte** (`script_has_option`, jamais en l'exécutant ; à distance, `grep` dans la sonde) : un `esde-install` plus ancien que le paquet ignore les arguments inconnus et lancerait l'installation interactive (« ES-DE semble déjà installé… », constaté) — en local le manager fait alors la copie lui-même (`copy_esde_config`, même règle : `~/ES-DE/custom_systems`, `<ROMDirectory>/tools/`, lanceur existant non écrasé), à distance il refuse avec un message « mettre à jour l'image du poste » (la copie ne peut pas être faite à moitié à travers SSH). La suppression est générique (retrait GearLever, AppImage, `.desktop`, icônes) sauf OpenCode 2, qui passe par `opencode2-remove` (CLI npm, symlink, entrées Dolphin + `mimeapps.list`, MCP Lightpanda) : **configuration, sauvegardes, jeux et sessions ne sont jamais touchés** (`~/ES-DE`, `~/Roms`, `~/.config/opencode`, `~/.config/ai.opencode.desktop`, `~/.local/share/opencode`). Supprimer OpenCode 2 arrête son serveur de fond — donc les sessions ouvertes sur ce poste (y compris une session lancée par SSH) ; `opencode2-remove` absent du poste → suppression désactivée (pas de retrait à moitié). GearLever absent → installation/mise à jour désactivées, suppression toujours possible ; script absent de l'image → bouton désactivé avec l'explication en infobulle. Les six cartes défilent (`QScrollArea`) pour tenir sur un écran 800 px.
- **Configuration avancée** (remplace `gablue-config`, qui appelait `ujust` dans konsole) : dialogue à **cinq cases à cocher** — protections contre les failles du processeur (`mitigations=off`), correctif CPUID pour certains jeux (`clearcpuid=514`, ex-`ujust cpuid-fix-on/off`), mode ERTM du Bluetooth (`bluetooth.disable_ertm=1`), **HDMI 2.1 sur GPU AMD** (`amdgpu.dcfeaturemask=0x402`, ex-`ujust configure-amd-hdmi21`) et émulation CPUID fault (`cpuid_fault_emulation`, ex-`ujust cpuid-emu-on/off`) — avec un seul bouton **« Appliquer »**, actif seulement si une case diffère de l'état du poste. Les **quatre** kargs partent en **un unique** appel à `/usr/libexec/gablue-kargs` (un déploiement), l'émulation CPUID dans `/usr/libexec/gablue-cpuid-emu on|off` (elle charge un module et occupe SVM, donc KVM) ; fermer avec des cases modifiées demande confirmation. Les deux helpers sont en NOPASSWD : **aucune invite de mot de passe** sur un poste Gablue. Les cartes des protections du processeur, d'ERTM, d'HDMI 2.1 et de l'émulation portent une **pastille de conseil** (`recommendation_badge`/`set_recommendation`, `uiutil`) : « ✓ Conseillé » en vert quand le choix courant suit le conseil, « Conseillé : cocher|décocher » en orange quand il s'en écarte — **le texte dit l'écart**, la couleur ne fait que le renforcer (une couleur seule se lisait mal). Elle disparaît tant que l'état est illisible. Celle du correctif CPUID n'en a pas, son bon réglage dépend du jeu. HDMI 2.1 est **recommandé désactivé** (FreeSync et fonctions 2.1, mais scintillements possibles sur certains écrans) : c'est un opt-in explicite. **L'état lu est celui du prochain démarrage** (`rpm-ostree kargs`, sans root), pas `/proc/cmdline` qui décrit le noyau en cours — sinon les cases reviendraient à l'ancienne valeur juste après l'application ; l'émulation est lue dans `/etc/modules-load.d/gablue-cpuid-emu.conf`. Les kargs ne prennent effet qu'au redémarrage, le dialogue le dit.
- **Services et variante** (`Services et variante…` du menu **Configuration** de la carte « Ce poste ») : dialogue local d'`dialogs/system.py`, ex-recettes ujust. **Cinq cases** — DisplayLink (service), Docker, couche Vulkan low-latency, pilote Wi-Fi Broadcom `wl`, historique atuin — avec un seul **« Appliquer »** et la valeur recommandée affichée (DisplayLink et Broadcom désactivés, low-latency et atuin activés ; **Docker n'a pas de recommandation**, il est simplement désactivé par défaut dans l'image et la case reflète son état réel). **Docker n'est affiché que sur une variante DX** (`docker_available(variant)`, suffixe `-dx`) : ailleurs le paquet n'existe pas. L'état vient de `systemctl is-enabled`, de la présence de `/etc/profile.d/vulkan-low-latency.sh` et de `/etc/modprobe.d/wl-enable.conf`, et de `atuin init bash` dans `~/.bashrc` ; l'application passe par `/usr/libexec/gablue-service`, `gablue-low-latency` et `gablue-broadcom-wl` (sudo -n) puis `/usr/bin/gablue-atuin` (sans privilège, fichiers de l'utilisateur) — un seul script, une seule tâche. **Atuin** : `on` installe ble.sh et branche un bloc balisé dans `~/.bashrc` (les lignes héritées d'ujust sont fondues dedans, jamais dupliquées) — l'`eval` porte **`--disable-up-arrow`** pour que la flèche Haut reste à ble.sh (historique du shell) et qu'atuin ne s'ouvre que par Ctrl-R, configuration du poste de référence (05/11/2026) ; `off` retire le bloc et ble.sh, avec instantané `~/.bashrc.gablue-atuin.bak`, mais **ne touche jamais** `~/.local/share/atuin` (historique) ni `~/.config/atuin`. **Variante** : liste `REBASE_VARIANTS` (main, main-dx, nvidia, nvidia-open, nvidia-open-dx) et bouton **« Basculer »** séparé, actif seulement si la variante choisie diffère de `local_variant()` (`rpm-ostree status --json`, déploiement `booted`, `gablue-<variante>` dans la référence d'image) ; confirmation explicite, téléchargement de l'image, effet au redémarrage. Si les helpers ne sont pas dans l'image, les cases sont désactivées avec « reconstruction requise » plutôt que de lancer des commandes absentes.
- **Options de gwine** (`Options de gwine…`, local et distant) : lit `~/.local/share/gwine/options` (`dxvk_mode`, `display_mode`, `xbox_default`, SSH pour un poste distant) et applique par gwine lui-même — `gwine --dxvk-async|--dxvk`, `gwine --wayland|--x11`, `gwine --xbox-on|--xbox-off` (tout ou rien ; le filtre `--xbox-ds4`/`--xbox-dualsense` reste en CLI) : le fichier garde son format et le préfixe reçoit les DLL DXVK correspondantes. Conseil affiché sur les trois réglages : DXVK standard (pas d'async), X11 plutôt que Wayland natif, Xbox 360 désactivé. Effet au prochain lancement de jeu, aucun privilège, journal en direct.
- **Priorité au premier plan** (`Priorité au premier plan…`, local et distant) : ex-`ujust foreground-booster-enable/disable`, refait sans passer par ujust — `kwriteconfig6 --file kcgroupsrc --group 'Foreground Booster' --key autostart true|false` puis `systemctl --user restart|stop plasma-foreground-booster.service` (best-effort : à distance sans bus de session, le fichier reste ce qui compte à la prochaine connexion). Recommandé : activé.
- **Tailscale** (`Tailscale…`, local et distant) : case activée/désactivée, état lu en une seule commande (`systemctl is-enabled|is-active tailscaled`, `tailscale debug prefs` pour le serveur). À l'activation, le lien du **serveur de connexion** est demandé (`QInputDialog`, prérempli avec le serveur déjà configuré) et validé (`http://` ou `https://`, sans espace ni guillemet) : contrairement à `ujust tailscale-up`, aucun serveur n'est codé en dur. Application par `/usr/libexec/gablue-tailscale on --login-server URL|off` (NOPASSWD) : `tailscale up --operator=$SUDO_USER`, service + firewall en `on`, arrêt + désactivation en `off`. Recommandé : désactivé.
- **Opérations simultanées** (`start_task`) : chaque opération (mise à jour, redémarrage, réglages, copie de clé) est une fenêtre **non modale** rattachée à la fenêtre principale — plusieurs postes peuvent être traités en même temps, et la fenêtre principale reste utilisable. Les dialogues de configuration se ferment après « Appliquer » et laissent la tâche tourner ; `_tasks` garde les fenêtres vivantes, `completed` déclenche le rafraîchissement des cartes. Un `exec()` (modale) ne doit plus servir qu'aux dialogues qui rendent un résultat immédiat (ajout/édition de poste, choix de candidats).
- **Privilèges** : `privileged_prefix()` sonde `sudo -n /usr/libexec/gablue-cpuid-emu status` (0 = règle NOPASSWD présente) puis retombe sur `pkexec` (dialogue PolicyKit) — `sudo -n true` échouait toujours, même sur Gablue, et faisait passer toute action root par PolicyKit malgré la règle sudoers. Les réglages noyau, émulation CPUID, services, couche Vulkan, pilote Wi-Fi, rebase et Tailscale n'utilisent ni l'un ni l'autre : ils passent par les helpers `/usr/libexec` en `sudo -n` (sans invite). Aucune commande root n'est lancée sur le thread GUI.
- **Actions externes** : `gremote [-p port] user@host` (port non standard) et `dolphin sftp://user@host:port/` (IPv6 entre crochets). Lancement détaché (`start_new_session`) : fermer la fenêtre ne tue pas la session RDP ; sortie capturée et affichée seulement si le code retour est ≠ 0, sauf le 131 de `sdl-freerdp` (fermeture normale de la fenêtre RDP) et les arrêts demandés depuis l'app.

PYTHONPATH=src/gablue-manager python3 -m unittest discover -s src/gablue-manager/tests -v
